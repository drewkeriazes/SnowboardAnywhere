# FEAT-059 Moguls Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Mogul fields appear on the runs where Vail really has them, at real spacing, and the rider bounces over them in physics as well as seeing them in the terrain.

**Architecture:** The pipeline scores each run (grooming reports, difficulty, slope, aspect, lift traffic, exclusions) and paints a per-cell mogul amplitude raster at 2 m, written as a greyscale tile set `moguls/` next to `ao/`, plus a `mogulScore` per run in features.json. The client adds a procedural fall-line-aligned staggered bump function (`terrain/Moguls.ts`) on top of the DEM inside `Pack.terrainHeight` (physics, and therefore `groundNormal`) and inside `Pack.height` for chunks at 2 m or finer (render), so the board sits on what the player sees. Phase creeps uphill with the season date and new snow softens the bumps.

**Tech Stack:** Python (numpy, scipy.ndimage, PIL) in `pipeline/`; TypeScript + Three.js in `game/`; node check scripts built with esbuild in `game/tools/`.

**Spec:** GitHub issue #92 (FEAT-059). Brainstorm outcome (Drew, 2026-11-09): a happy medium between look and feel, with fidelity to the real mountain the top priority. Calls made by the planner: fields change with the game's date and snow settings; placement is a separate greyscale tile set.

### Task 1: Pipeline scoring module

**Files:**
- Create: `pipeline/moguls.py`
- Create: `pipeline/tests/test_moguls.py`

**Interfaces:**
- Produces: `run_mogul_score(run: dict, slope_med: float, aspect_mean: float | None, groom_frac: float | None, mogul_tag: bool, near_lift_top: bool) -> float` in 0..1.
  - `run` has `difficulty`, `gladed`, `name`, `area`.
  - `slope_med` degrees, median along the centre line; `aspect_mean` degrees clockwise from north of the downhill direction, or None when flat; `groom_frac` = groomNights / total report nights, None when the resort has no reports.
- Produces: `slope_window(slope_deg: np.ndarray | float) -> same` in 0..1: smoothstep up 15..20, 1 at 20..35, smoothstep down 35..40.
- Produces: `paint_field(target, pts, half_width, value, res, x0, y1, edge=3.0) -> None`: paints `value` along the polyline corridor, fading linearly to 0 over the outer `edge` metres, taking the max with what is there. Row 0 = north, like `rasterize_corridor` in build_pack.py. `x0` is the west edge and `y1` the north edge of the raster in the same coordinates as `pts`.
- Produces: `paint_polygon(target, pts, value, res, x0, y1) -> None` for closed `area` runs (PIL ImageDraw.polygon onto a temp uint8 raster, then max).

Scoring rule (the values the spec fixes):
- `mogul_tag` True: return 1.0 regardless (OSM `piste:grooming=mogul`).
- Return 0 when `gladed`, or `difficulty` in (`novice`, `easy`), or `name` matches `road|catwalk|cat track|traverse|cutoff|access|skiway` (case-insensitive), or `slope_med < 12`.
- grooming term `g`: None -> 0.7 (unknown); groom_frac 0 -> 1.0; 0 < frac <= 0.2 -> 0.8; 0.2 < frac <= 0.5 -> 0.4; frac > 0.5 -> 0.0.
- difficulty term `d`: expert 1.0, advanced 0.9, freeride 0.8, extreme 0.6, intermediate 0.5 (only if groom_frac is 0 or None, else 0), other 0.
- slope term `s = slope_window(slope_med)`.
- aspect term `a`: 1.0 when aspect within 60 deg of north, 0.85 for east and west quadrants, 0.7 for south (within 60 deg of 180); None -> 0.85.
- traffic term `t`: 1.0 when `near_lift_top`, else 0.8.
- score = g * d * s * a * t, clipped to 0..1.

### Task 3: Client mogul shape function

**Files:**
- Create: `game/src/terrain/Moguls.ts`
- Test: `game/tools/mogulcheck.mjs` (unit part; the ride part comes in Task 6)

**Interfaces:**
- Produces: `export const MOGUL_SPACING = 5.7` (m), `export const MOGUL_MAX_AMP = 1.0` (m), `export const MOGUL_CREEP_M_PER_DAY = 0.08`.
- Produces: `export function mogulHeight(x: number, y: number, amp: number, fallX: number, fallY: number, creepM: number): number`: the bump height in metres, 0..amp, for pack coordinates, with `(fallX, fallY)` the downhill direction (any length, normalised inside; a zero vector means east) and `creepM` the uphill phase shift in metres.
  - u = along-fall coordinate (positive downhill), v = across. S = MOGUL_SPACING. Staggered field: `f = sin(2π(u + creepM)/S + j1) * sin(2π v/S + j2)` with j1, j2 low-frequency value-noise jitter (wavelength about 25 m, amplitude ±0.8 rad) from a hash of floor(x/25), floor(y/25) with bilinear blend. Height `h = amp * pow(0.5 + 0.5 f, 1.6)` (rounded tops, sharper troughs). amp clamped to 0..MOGUL_MAX_AMP.
- Produces: `export function fallFrom(baseH: (x: number, y: number) => number, x: number, y: number, out: number[], d = 6): number[]`: unit downhill vector from central differences at ±d; (1, 0) when flat.

- [ ] **Step 1: Write the failing unit checks** in `game/tools/mogulcheck.mjs` (esbuild bundle, pattern copied from `presscheck.mjs`): amp 0 -> 0 everywhere; amp 0.8 over a 60 x 60 m grid at 0.25 m steps gives max in [0.75, 0.8] and min < 0.02; amp 5 clamps to max <= 1.0; a profile along the fall line over 57 m has 8 to 12 maxima; `creepM` 2.85 moves the profile by half a period (correlation of the two profiles < -0.5); `fallFrom` on a plane falling to -y gives (0, -1) within 1e-3 and (1, 0) on a flat plane.
